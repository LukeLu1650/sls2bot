# GPT‑6.2 Sol 交接提示词

当前只做骨头人标准模式，A0 起步、A10 验证。每段可作为一个独立开发任务。开始前读本仓库的 `README.md`、`docs/windows-baseline.md` 和已提交的 `results/`，检查工作树；记录输入版本、运行命令、完成的局数和剩余问题。以下任务只有在明确启动时才执行。每次运行设定局数、步数和墙钟上限，等子进程退出再交付。

## 任务 A · 提高骨头人的起步胜率

> 在本地原生 Windows、v0.113.1 的标准模式下，把“常常直接结束回合”的 18.10M 参数骨头人策略改进为有效的 A0 战斗起点。先阅读 `scripts/necro_policy.py`、`scripts/beta_env.py` 及逐局动作计数。检查同类手牌是否能根据费用、伤害、格挡、目标、Osty 和灾厄区分。用只读当前局面的简单教师演示：可以击杀时优先击杀，否则按可见敌方意图决定格挡与攻击。以 4 个新训练种子或 512 个多候选决策为首批上限，先更新读出头；记录训练交叉熵和可用决策数。留出种子独立，只在同一批开发种子上比较原始网络、教师、新网络的完整局数、第一幕通过率和终局楼层。现有 8 个历史种子已公开用于开发，最后对外报告时预先登记一批全新的测试种子。若短训管线通过，再提出单个有界 PPO 更新所需的最小改动。不要在这项任务中发起长时间训练。

## 任务 B · 校验 Windows 宿主

> 验证标准模式真实客户端与无画面宿主的一段轨迹。固定游戏 commit、种子、进阶、单人全解锁和行动序列；第一次最多两个种子、每个种子 30 个决策。优先比较骨头人手牌和费用、Osty 血量、敌人意图、灾厄结算和商店。找出第一个不一致的步骤，附最小状态差异。涉及真实客户端时使用隔离的实验档；若缺少安全的实验档，就先完成回放比较器和宿主侧记录。检查稳定模型在相同种子上的动作序列能否重现，并保留未验证的环节。

## 任务 C · 修复标准模式的 Dense Vegetation 事件

> 复现标准 A10 种子 `8668D8L9UBCT`，使用规则对照第六局的 `RulePolicy(5)`。在第一幕第 3 层记录 Dense Vegetation 的 Rest 选项、治疗前后状态及随后的强制战斗。定位无画面宿主缺失的上下文，修复后验证恢复正确生命、进入预期战斗以及动作合法性；保留玩家可选的两个选项。把最小源码补丁和补丁后宿主哈希存入本仓库，用冻结种子重跑并与原异常记录并列。先只跑这一局，每局最多 1,024 步、90 秒。

## 任务 D · 有依据地选择 Windows 或 WSL

> 在 Windows 实现原生训练优先。使用相同模型、相同游戏 DLL 和观测协议，分别量测 1、2、4 个 Windows 宿主的端到端决策吞吐、训练更新耗时和显存。每档预热后最多测 60 秒。若准备迁移训练器至 WSL，先说明 Windows 端哪项能力缺失或瓶颈在哪，再测 WSL 连到同一 Windows 宿主的对照；两边使用相同批大小和种子。交付原始样本、每秒决策数和明确选择。到达预算后停止所有采样器。
