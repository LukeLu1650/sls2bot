# 骨头人当前模型与可选动作

当前模型固定在原生 Windows 的《杀戮尖塔 2》public-beta v0.113.1 标准模式。它有 18,099,905 个参数，6 层 Transformer、宽度 256、4 个注意力头。环境每次返回当前决策和可用候选。模型一次前向给所有候选打分，执行最高分动作，然后等游戏返回新局面。一次出牌与一次结束回合分别算一个决策。[策略](../scripts/necro_policy.py) · [动作枚举](../scripts/beta_env.py)

## 标准模式候选动作

| 当前界面 | 可选动作 | 候选条件 |
| --- | --- | --- |
| 战斗 | 打出手牌；需要指定敌人时，每个活着的目标对应一项 | 游戏标记为可出的手牌；同名的两张牌按手牌实例区分 |
| 战斗 | 使用药水；敌方单体药水按目标展开 | 只枚举战斗内的主动药水 |
| 战斗 | 结束回合 | 战斗决策中始终可用 |
| 地图 | 进入一个当前可达的房间 | 从宿主返回的当前位置选项中选择 |
| 涅奥和事件 | 选一个可用选项 | 锁定选项排除 |
| 休息点 | 选择睡觉、升级等当前可用项目 | 具体项目由游戏决定；若触发选牌，再处理独立选牌提示 |
| 卡牌奖励 | 选一张或跳过 | 跳过取决于当前奖励允许的操作 |
| 独立选牌和卡包 | 选择符合数量约束的牌组，或选一个卡包 | 多牌组合最多 256 项，允许选零张时提供跳过 |
| 商店 | 买卡、遗物或药水、进入删牌选择、离开 | 检查标价、库存与金币。买药读取游戏实际空栏，可识别遗物增加的容量 |

宿主自动领取金币及一部分非卡牌奖励，丢弃药水及战斗外主动用药尚未接入。有动作候选的场景也可能遇到宿主实现问题。例如此前基线的 Dense Vegetation / Rest 会出现空引用。错误和决策步数上限单独记录。

## 模型看见什么，训练到了哪里

推理输入包括血量、格挡、能量、手牌和费用、敌人血量与意图、Osty 的公开状态，以及当前候选动作。此次加入了单次出牌预览中的伤害、可能击杀、可挡伤害、召唤、灾厄和抽牌数。种子和未知的抽牌顺序留在宿主。模型的动作分数用于同一步候选排序，回放里的柱长按当步展示分数拉伸。[编码与训练](../scripts/train_standard.py)

本轮在上一版 A0 权重上继续训练。用四个种子的 50 个多候选决策、10 轮模仿学习，仅更新打分头，平均训练交叉熵从 1.54 降至 1.27。8 个独立开发种子的首战通过数由 1 场提高到 8 场，规则教师同为 8 场。改动同时加入了战斗特征和示范训练，这次对照没有单独量化两者各自的贡献。地图与构筑暂时没有专项训练。三局整局试跑有一局在 A0 第 13 层死亡，两局在第 4 层出现宿主异常。[逐局报告](../results/windows-v0.113.1/standard-continuation/report.json)

回放第二局的第 3 个决策中，Nibbit 预告打 12，骨头人有 3 点能量。模型给 Bodyguard 打了 0.10，给三张 Defend 打了 −0.23、−0.25、−0.27，于是先召唤 Osty。之后重新读取局面，依次选择 Defend 和 Spirit of Ash。能量耗尽后只剩结束回合。这些分数来自当局模型，分别对应实际游戏中的四次决策。[真实回放数据](../results/windows-v0.113.1/standard-continuation/replay.json)
