# 骨头人 · 从参考模型到实机策略

首个目标是在固定版本的标准模式中，让一套策略完成骨头人的所有单人决策，包括打牌和选目标、药水、奖励选牌或跳过、事件、路线、商店与休息点。最终指标是预先留出的新种子上的整局通关率，同时报告各幕通过率。开场选项到终局都由同一评测协议驱动。

## 1. 当前基线与历史参照

1. 在本机使用 [Windows v0.113.1 实验](windows-baseline.md) 完成同角色、同构建对照。首版使用原生 Windows，目标网络的实际前馈宽度为 5,024。下面第 2、3 项和 Bash 命令仅适用于有 Linux v0.107.1 副本时的历史参照。
2. 在相同版本用上游 `necrobinder.bin` 评测骨头人。发布页给出的参考值是 A10 的 **1.6% / 2,560 局**。这是上游参考网络的结果。摄政王适合验证管线；比较新网络的强弱时，使用相同角色的模型。公共发行包也提供 `training_inputs/necrobinder.pt` 和继续训练方案 `a10_push`。[发布结果与权重包](https://github.com/HalfVulpes/sts2ai/releases/tag/v1.0) · [训练预设](https://github.com/HalfVulpes/sts2ai/blob/d667489560cc46154638e1208ff032ed96707aa3/scripts/train.py)
3. 示例沿用摄政王文档的 Bash 变量。首次四局检查后，固定一个开发种子集来选 checkpoint，再封存另一批独立的随机评测种子。将两批种子按本构建的协议转换为数字，传给训练器的 `--reserved-seeds`。比较同一构建的模型时，使用相同的角色、解锁内容、难度和种子。

```bash
cd "$ASSETS"
curl -fL --retry 2 "$release/necrobinder.bin" -o necrobinder.bin
awk '$2 == "necrobinder.bin" || $2 == "*necrobinder.bin" {print; found=1} END {exit !found}' SHA256SUMS > necrobinder.sha256 &&
  sha256sum -c necrobinder.sha256 || exit 1
cd "$UP"
mkdir -p "$ROOT/runs"
OUT=$(mktemp -d "$ROOT/runs/necro-base-A10-XXXXXXXX")
python3 scripts/evaluate.py --character necrobinder --ascension 10 --workers 2 \
  --model "$ASSETS/necrobinder.bin" --seeds CHECK00001,CHECK00002,CHECK00003,CHECK00004 --out "$OUT"
```

## 2. 设计观测与动作

| 决策信息 | 编码与验收样例 |
| --- | --- |
| 骨头人和召唤物 Osty | 玩家和 Osty 用独立实体表示。记录画面可见的生命、格挡、状态和召唤信息。做三组回放，覆盖 Osty 存活、受击消失、重新召唤，对齐前后状态和合法目标 |
| 敌人与灾厄（Doom） | 按敌人记录可见意图、血量、格挡、灾厄层数及公开效果。用双敌场景检查目标身份，回放灾厄触发前后的行动和终局判定 |
| 手牌与灵魂牌（Soul） | 每张可选牌保留实例、费用、升级和可见修饰。抽牌堆按已知组成编码，隐藏顺序；在产生、抽到、打出、消耗灵魂牌的节点比较实机和宿主 |
| 奖励、事件与商店 | 当前屏幕、可选项及目标各自有稳定标识。检查“跳过奖励”“离开商店”和多阶段选牌。动作位置变化时按语义标识比较 |

实战部署约束为单次前向传播加合法动作掩码，按最高分执行，平分时用稳定的动作次序。策略只接收当前观测和候选动作。种子、RNG 内部状态、隐藏抽牌顺序、未来分支和回档接口均由宿主隔离。上游论文披露编码中含敌人下一招的内部 ID，比玩家显示的意图更详细；上游也自动领取金币等单选项，并用固定规则处理 Crystal Sphere 小游戏。保留一份原版基线，自己的“玩家可见”实验单独记录特征删改及自动处理的选择。做遮蔽测试：两个可见局面相同、隐藏信息不同的状态，编码和动作分数应相同。[论文 §3.1–3.2](https://arxiv.org/html/2611.12088v1#S3)

## 3. 如何做到约 1,809 万参数

原视频公开的形状是 6 层、宽度 256、4 头，每头维度 64。仅凭这些数值无法唯一推导参数量。这里给出一个可实现的候选，前馈宽度属于本项目设计选择。[原视频](https://www.bilibili.com/video/BV19Bxq6wE9k/)

| 设计 | 骨头人参考基线 | 本项目候选 |
| --- | --- | --- |
| 层数 / 宽度 / 注意力头 | 6 / 256 / 8 | 6 / 256 / 4 |
| 每层前馈隐藏宽度 | 1,024 | 4,768（沿用论文词表的历史设计） |
| 总参数 | 6,568,453（论文） | 约 18,092,485（按同词表、嵌入和输出头推算） |
| 初始化 | 上游骨头人权重 | 先随机初始化；需要加速时另设蒸馏实验 |

固定宽度时，多头数改变注意力分组；标准 QKV 投影的参数总数保持相同。六层两层式前馈网络扩宽的增量为 `6 × (4768 − 1024) × (256 + 1 + 256)`。实现时以 `sum(p.numel() for p in model.parameters() if p.requires_grad)` 为准，记录实际词表和各模块参数；给新模式增加实体或头时重新计数。上游的 8 头 checkpoint 有不同的注意力分组及前馈形状，目标模型需要独立预设和权重标识。参考实现修改落点是 `model.py` 的预设、训练选择、权重导出元数据和 C# 加载器。[原始网络](https://github.com/HalfVulpes/sts2ai/blob/d667489560cc46154638e1208ff032ed96707aa3/train/sts2ai/model.py) · [实机推理实现](https://github.com/HalfVulpes/sts2ai/blob/d667489560cc46154638e1208ff032ed96707aa3/shared/Inference/PolicyNet.cs)

Windows 实现采用 4,096 桶特征嵌入、动作候选实体及单一打分头，在代码中直接统计所有权重元素，合计 18,099,905。首轮实验冻结主干，仅训练读出向量；完整 PPO 需要增加价值头、梯度训练及采样器。[当前模型](../scripts/necro_policy.py)

## 4. 训练、评测和部署

| 阶段 | 怎么做 | 进入下一阶段的依据 |
| --- | --- | --- |
| A0 学会操作 | 在单人标准模式以 PPO 从随机起点训练。训练时在合法动作中按分布采样，同时训练价值头。通关作为主要奖励，楼层、精英和 Boss 的少量奖励可沿用论文作为首个对照 | 相同种子可重放，非法动作数和引擎错误为零。查看策略能否结束回合、选目标、离开商店，并在新种子上超过随机合法动作基线 |
| 逐步提高难度 | 固定每轮新采样决策预算，先 A0、后中等进阶、最后 A10。每轮分别记录吞吐、显存、通过第一幕和整局获胜的局数。对失败集中的战斗，可在训练专用种子上从中间状态重练 | 与同预算的普通开局 PPO 做对照。验证集从正常开局评估进步；若只在重练片段中变强，继续保留普通开局采样 |
| 冻结候选 | 用开发集选一个 checkpoint，再开启封存的整局测试集。初筛可用 256 局；若胜场稀少或差异很小，预先约定扩到 1,000 局以上。报告种子数、胜场、Wilson 95% 区间及同种子胜负翻转数 | 比较骨头人原始权重、同观测的小网络、目标网络。披露训练决策预算、独立训练种子和观测差异，单次连胜仅作为演示 |
| 接回实机 | 导出 EMA 权重，保存模型与词表指纹。对同一批真实观测比较 PyTorch 和 C# 的动作分数、最高分动作及耗时，再在匹配构建的本地游戏中单步和整局运行 | 覆盖战斗与非战斗动作。记录每次实际决策的前向次数、搜索调用次数、P50/P95 延迟、自动处理项。目标分别是每次策略决策 1 次前向、0 次搜索 |

引擎错误单列并计入总局数。记录胜场的同时保存到达幕数与死因，以便判断问题出在早期保血、构筑，还是终局战斗。采样阶段的重练允许重复经历局面；封存评测和实机演示都从正常开局一次走到终局。[PPO、重启课程与评测方法](https://arxiv.org/html/2611.12088v1)
