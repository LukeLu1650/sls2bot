# 杀戮尖塔 2 · 骨头人零搜索策略

目标是让死灵契约师（Necrobinder，骨头人）独立完成单人爬塔。每个决策点只读一次玩家可见状态，模型给当前合法动作打分，直接执行最高分动作。目标网络约 1,809 万参数，6 层 Transformer、宽度 256、4 个注意力头。第一轮用摄政王验证训练链路，最终用未参与训练的种子衡量骨头人的整局表现。

## 当前进度 · 2026-11-23

本机已有 WSL2 Ubuntu 24.04、Python 3.12.3、C 编译器，WSL 能看到 RTX 5070 Ti Laptop（12,227 MiB）。检查时 Ubuntu 默认环境找不到 .NET SDK 和 PyTorch。已找到的 Steam 安装是 Windows v0.113.1，目录中缺少 Linux 程序集。上游源码已在本地固定到 v1.0；首次跑局需要另备通过校验的 Linux 游戏 v0.107.1。当前交付为实验仓库和操作流程，胜率与速度留待实际跑局填写。

本仓库跟踪实验入口和文档。上游源码放在 `external/sts2ai/` 独立检出；官方游戏文件仅从自己的安装导入。模型包放在 `artifacts/`，每轮输出写入新的 `runs/` 子目录。重新检出本仓库后，按摄政王流程恢复同一上游版本。

研究基线来自 Chen 与 Xie 的 STS2 零搜索 PPO 工作；上游公开了摄政王和骨头人的基础权重。视频中的 1,809 万参数、29.4 亿次决策和内测成绩是作者披露的数据，视频项目闭源，本仓库据此设定架构目标。两组结果各自保留角色、版本和评测口径。[原视频](https://www.bilibili.com/video/BV19Bxq6wE9k/) · [论文](https://arxiv.org/abs/2611.12088) · [上游代码与权重发布页](https://github.com/HalfVulpes/sts2ai/releases/tag/v1.0)
